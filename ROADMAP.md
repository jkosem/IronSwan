# IronSwan — product roadmap

Approved product direction, 26 November 2026. Future milestones are flexible; no release dates are committed.

## Vision

A simple, elegant, open-source way to create, design, read and independently publish books on the web. Readers need comfortable, uninterrupted reading; authors need uncomplicated publishing; designers need creative control. Cold Forest is a real-world test book, not the software itself.

## Principles

User first; simplicity; elegance; independence; design-led development; performance; accessibility; testability; longevity. Preserve flat HTML, CSS, JavaScript and Markdown, no required build step, framework, database or runtime dependencies. Remove complexity rather than adding features for their own sake.

## Development and release process

1. Identify the user problem and intended outcome.
2. Design and specify the simplest viable solution before implementation.
3. AI implements, reviews code and runs technical tests, preferably in one cohesive PR per release.
4. AI provides a working browser preview and a change-specific user acceptance testing (UAT) checklist directly in the PR description using GitHub Markdown task boxes.
5. The owner tests the experience, ticks completed items, records failures, and approves the release. AI addresses failures in the same PR wherever practical. Re-test changed behavior.
6. Merge only with explicit owner approval and required passing checks; tag the release, update the changelog and record decisions in project memory.

### Mandatory PR acceptance checklist

Every PR requiring owner review must explain the user problem, link to the working preview, and contain unchecked GitHub task boxes generated by AI from the actual changes. Each item states the action, where/device when relevant, and the expected visible behavior. Include relevant regression checks and before/after comparisons. Keep technical verification separate; the owner must not need to run a terminal or inspect source code. Do not pre-tick owner tests. Record failures or untested items and resolve them or obtain explicit owner acceptance of exceptions before merge. A green CI run is not a substitute for owner acceptance.

The owner is product owner, design director and final acceptance tester. AI handles technical implementation, review, testing and documentation. Measure releases by simplicity, usability, elegance, reliability and maintainability rather than feature or commit count.
